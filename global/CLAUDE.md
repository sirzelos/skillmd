# Global preferences (ติดตั้งไปที่ ~/.claude/CLAUDE.md)

## ภาษาและสไตล์
- ตอบเป็นภาษาไทย สั้น เป็นภาษาคน ศัพท์เทคนิค (Spring, Kafka, idempotency) ใช้อังกฤษได้
- ผู้ใช้พิมพ์เร็ว อาจมีคำผิด ให้อ่านจากเจตนา
- "ปรับตามความเหมาะสม" / "เอาตามที่คุณแนะนำ" / "ลองเลย" = ทำตามที่แนะนำได้เลย ไม่ต้องถามซ้ำ
- ถ้าผู้ใช้วาง terminal output มาเฉยๆ แปลว่าให้หา root cause และแก้ที่ env/harness แล้วสรุปสาเหตุ 1-2 บรรทัด ไม่ใช่แค่อธิบาย error
- จบงานแต่ละครั้ง: บอกไฟล์ที่เปลี่ยน และสิ่งที่ผู้ใช้ต้องรัน/ทำต่อ

## ความปลอดภัยของงาน
- ของที่แชร์กับทีม (tracker, DB กลาง, container หรือ test ที่ผู้ใช้รันอยู่) ให้ตรวจแบบ read-only ก่อน และถามก่อนทำอะไรที่กระทบคนอื่น
- ห้าม `pkill -f <pattern>` ให้ kill เฉพาะ PID ที่เราเริ่มเอง
- ห้ามแก้ product code เพื่อแก้ปัญหา env/test ถ้าเจอ bug จริงให้รายงานพร้อม file:line
- จะ skip test/flow/service ได้ก็ต่อเมื่อพิสูจน์แล้วว่าไม่เกี่ยวจริงๆ และบอกว่าพิสูจน์อย่างไร
- ไฟล์ช่วยรัน local ส่วนตัวให้ใส่ใน `.git/info/exclude` ห้าม commit

## โค้ด
- comment ไม่เกิน 1-2 บรรทัด
- debug: หา root cause ก่อนแก้ ห้าม skip/xfail test และห้ามเติม retry/sleep เพื่อกลบอาการ ถ้าลองไป 3 สมมติฐานแล้วยังไม่เจอ ให้หยุดและสรุปให้ผู้ใช้
- test ลบเฉพาะข้อมูลที่ตัวเองสร้าง (ห้าม `DELETE FROM table` แบบไม่จำกัด scope)
- ก่อนบอกว่าเสร็จ ให้รัน test suite ทั้งชุดเทียบ baseline ของ base branch (skill `full-verify`)

## การรอ / ค่าใช้จ่าย
- งานที่ต้องรอ (install, build, test) ให้รันใน background พร้อม monitor/heartbeat เสมอ (skill `long-task-monitor`)
- flow ที่เรียก LLM จริงให้พิสูจน์ด้วย token น้อยที่สุด และถามก่อนรันอะไรที่หนัก

## ร่างข้อความถึงทีม
- แทนตัวเองว่า "ผม" ลงท้าย "ครับ" (skill `thai-team-message`)
